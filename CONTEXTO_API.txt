Estoy trabajando con dos aplicaciones Laravel locales que se comunican mediante una API:

- Dr. Sam: `C:\laragon\www\dr-sam`
- Mezclas Pro/CBTA: `C:\laragon\www\mezclaspro`
- Dr. Sam se ejecuta en `http://127.0.0.1:8000`
- Mezclas Pro se ejecuta en `http://127.0.0.1:8080`

OBJETIVO

Continuar desarrollando y probando la integración para enviar solicitudes de mezclas nutricionales (NPT) y oncológicas desde Dr. Sam hacia Mezclas Pro.

CONFIGURACIÓN

El `.env` de Dr. Sam contiene:

```env
CBTA_BASE_URL=http://127.0.0.1:8080
CBTA_API_TOKEN=TOKEN_SANCTUM_GENERADO_EN_MEZCLAS_PRO
CBTA_API_TIMEOUT=10
CBTA_API_CONNECT_TIMEOUT=3
```

No mostrar, copiar a Git ni reemplazar el token real sin autorización.

El token se genera desde Mezclas Pro con:

```powershell
php artisan integration:issue-drsam-token --provision
```

El valor completo generado se coloca únicamente en `CBTA_API_TOKEN` de Dr. Sam.

ESTADO ACTUAL

La comunicación ya funciona. Se comprobó mediante:

```powershell
php artisan cbta:check-catalog DRSAM-DEMO --type=npt
php artisan cbta:check-catalog DRSAM-DEMO --type=oncology
```

Ambos comandos deben devolver el catálogo, su versión y número de productos. Un error `401` significa token inválido; `cURL error 7` significa que Mezclas Pro no está ejecutándose o que el puerto es incorrecto.

FUNCIONAMIENTO DE LA INTEGRACIÓN

Dr. Sam:

- Consulta catálogos NPT y oncológicos de Mezclas Pro.
- Prevalida productos, presentaciones, unidades, diluyentes e inventario.
- Genera solicitudes de manera idempotente.
- Guarda la relación en `mixture_integrations`.
- Sincroniza estados y conserva errores y número de intentos.
- Puede consultar documentos y remisiones generadas por Mezclas Pro.
- Reintenta solicitudes pendientes mediante el programador de Laravel.

Mezclas Pro:

- Recibe las solicitudes en `/api/internal/v1`.
- Autentica mediante Laravel Sanctum.
- Materializa las solicitudes en los módulos nutricional u oncológico.
- Mantiene el identificador remoto, estado, inventario y trazabilidad.
- Expone catálogos, prevalidación, solicitudes, estados, documentos y remisiones.

UNIDAD DE PRUEBA

La unidad utilizada en las pruebas es:

```text
DRSAM-DEMO
Hospital General Demo Dr. Sam
```

Debe existir y estar correctamente relacionada en ambos sistemas.

AUTORIZACIONES

Antes del flujo operativo, cada solicitud debe aprobarse desde sus perfiles correspondientes:

NPT:

- Enfermería.
- Farmacia intrahospitalaria.

Oncológica:

- Centro Oncológico.
- Farmacia intrahospitalaria.

Cada perfil solo debe modificar su propia autorización. Los intentos realizados desde otro perfil deben responder con bloqueo `403`.

COMANDOS ÚTILES

Comprobar catálogos:

```powershell
cd C:\laragon\www\dr-sam

php artisan cbta:check-catalog DRSAM-DEMO --type=npt
php artisan cbta:check-catalog DRSAM-DEMO --type=oncology
```

Reintentar sincronizaciones pendientes:

```powershell
php artisan cbta:sync-mixtures --limit=50
```

Limpiar configuración después de modificar `.env`:

```powershell
php artisan optimize:clear
```

No se necesita `queue:work` para el flujo actual, salvo que existan trabajos pendientes en la tabla `jobs`. Los reintentos de integración dependen principalmente de `schedule:work`.
